# 需求判断 SOP：从需求到界面方案

接到新建或修改界面的需求时，先读本文件，再动手选组件。它回答「这类需求该用什么界面和交互」，
产出一份方案单；细则仍在各专题文件里，本文件只负责分流。

分流表是把现有规则按需求重新组织的建议默认，不新增出处。标注「默认」的阈值可按项目调整并记录；
与专题文件冲突时以专题文件为准，与项目已有模式冲突时按第 7 节处理。

## 流程总览

1. **写任务陈述**：谁，在什么场合，对什么对象，做什么，多频繁，做错的代价是什么。
2. **补齐六个事实**（第 1 节）。拿不到的按默认值走，并在方案单里标成「假设」。
3. **判定需求类型**（第 2 节），得到页面骨架和必读参考。
4. **逐项做交互判断**（第 3 节），每条写成「因为……所以用……」。
5. **列状态矩阵**（第 4 节），再写方案单（第 5 节）。方案单先给用户看，再实现。
6. **实现后过** [审查清单](checklist.md)，不适用项写明原因。

一句话需求（如「加个删除按钮」）也走这六步，只是每步只写一行。

## 1. 先确认的六个事实

| 事实 | 从哪里得到 | 拿不到时的默认 |
|---|---|---|
| 使用频率：一次性、偶尔、每天多次 | 需求描述、现有入口位置 | 偶尔使用，优先易懂而非高效 |
| 对象数量级：个位、几十、上千以上 | 接口分页参数、真实数据 | 几十条，并验证 0 条和上千条 |
| 可逆性：可撤销、可恢复、不可逆 | 后端是否有软删除或撤销接口 | 不可逆，按确认流程处理 |
| 等待时长：瞬时、几秒、更长或后台 | 接口实测或同类接口 | 300ms 到 2 秒，并验证慢请求 |
| 主设备：桌面键鼠、触屏、两者 | 现有页面的断点与访问数据 | 两者都要可用，320 CSS px 不丢功能 |
| 出错代价：低、丢输入、涉及金钱或对外发送 | 业务规则 | 会丢输入，失败时必须保留内容 |

需求里有两种合理读法，且选错会返工时，先问用户；其余情况按默认推进并写明假设。

## 2. 需求类型 → 页面骨架

一个需求可以命中多行，按主要任务选骨架，其余作为区块并入。

| 需求信号 | 骨架 | 必读参考 |
|---|---|---|
| 查看、管理一批记录 | 工具栏（搜索、筛选）+ 表格或列表 + 批量操作栏 + 分页 | [复杂组件](complex-components.md) |
| 填写并提交信息 | 字段少单页平铺，多且可分组用分组表单，有先后顺序用分步加确认页 | [表单](patterns.md#5-表单) |
| 修改偏好或配置 | 按任务分组的设置页，每页只用一种生效模式 | [保存](patterns.md#4-保存) |
| 按步骤完成一件事（开通、导入、结账） | 分步流程 + 确认页 + 明确的结果页，可返回上一步且不丢输入 | [表单](patterns.md#5-表单) |
| 与 AI 对话或让智能体执行任务 | 左右布局：会话列表 + 消息流 + 输入框 | [AI 对话](ai-chat.md) |
| 阅读文章或文档 | 上下布局，正文限制行长并居中 | [典型布局](layout.md#典型布局) |
| 上传或导入文件 | 文件选择按钮为主、拖放为辅，逐文件显示阶段 | [上传](complex-workflows.md#上传) |
| 快速查找并执行命令 | 模态对话框内的可编辑组合框 | [命令面板](complex-workflows.md#命令面板) |
| 首次进入、还没有数据 | 空状态说明用途并给一个主操作，不用盖住全页的导览 | [空状态](patterns.md#6-空状态) |
| 看指标或监控 | 默认：关键数字在上、趋势居中、明细在下；图表选型不在本规范内 | [覆盖范围](../SKILL.md#覆盖范围) |

营销落地页、品牌视觉、原生 App 控件不在范围内：只套用质量底线（对比度、焦点、响应式），风格另行决定。

## 3. 交互判断

### 3.1 内容放在哪一层

| 如果 | 那么用 | 不要 |
|---|---|---|
| 内容多，或需要独立网址、可分享、可后退 | 新页面 | 塞进对话框再加内部滚动和多级跳转 |
| 查看或编辑列表里的一项，同时要保留列表上下文 | 默认：侧边面板，窄屏改为整页 | 跳走后丢掉筛选和滚动位置 |
| 必须先处理才能继续，且内容很短 | [原生模态对话框](accessibility.md#原生模态对话框) | 用模态承载可以稍后再看的信息 |
| 贴着触发点补充少量信息或操作 | Popover | 在 Tooltip 里放链接或按钮 |
| 只有一句描述性文字 | Tooltip，且关键功能不依赖它 | 用它承载触屏上必需的说明 |
| 次要细节，偶尔才看 | 原地展开，见 [渐进披露](patterns.md#8-渐进披露) | 把常用内容藏起来换取「简洁」 |

### 3.2 让用户做选择

数量阈值为默认值。同一类内容全站用同一种控件。

| 如果 | 那么用 |
|---|---|
| 二选一，改了立即生效 | 开关 |
| 二选一，随表单一起提交 | 复选框 |
| 2 到 5 个互斥选项，需要一眼比较 | 单选组，用 fieldset 和 legend 命名 |
| 6 个以上互斥选项 | 原生下拉框；选项很多且需要搜索时用可编辑组合框 |
| 多选，选项少 | 复选组 |
| 多选，选项多 | 可搜索的多选组合框，已选项可见并可逐个移除 |
| 在同一对象的几个视图间切换 | 标签页 |
| 去往另一个对象或页面 | 链接或导航，不用标签页 |
| 邮编、账号、验证码等标识符 | 文本输入加数字键盘提示，不用 type=number |

自定义的菜单、组合框、标签页按 [键盘合同](accessibility.md#复合控件键盘合同) 实现；能用原生元素时不自造。

### 3.3 展示一批数据

| 如果 | 那么用 |
|---|---|
| 要按列比较、排序或批量操作 | 表格，见 [可排序表头与固定列](complex-components.md#吸顶表头与固定列) |
| 每项以图像或预览为主 | 卡片网格 |
| 每项一两行，主要用来扫读和点开 | 列表 |
| 一屏放得下 | 不分页 |
| 需要定位到某一条、回到某一页 | 分页，查询写进网址，见 [查询状态](complex-components.md#查询状态) |
| 信息流式浏览，不关心位置 | 默认：「加载更多」按钮，返回时恢复位置 |
| 上千项同屏 | 虚拟化，并保证搜索和导出能取到未挂载内容，见 [性能观感](performance.md) |
| 窄屏下的表格 | 局部横滚并固定标识列；列很少时可改成每行一张卡片 |
| 要对多项执行同一操作 | 复选加批量栏，见 [选择范围](complex-components.md#表头三态与选择范围) |

### 3.4 操作之后给什么反馈

完整分级见 [反馈](patterns.md#1-反馈按打扰程度选组件)。

| 如果 | 那么用 |
|---|---|
| 结果在眼前直接可见 | 只做行内状态变化，不额外提示 |
| 成功了，但结果不在视野内 | 轻提示，约 3 秒自动消失 |
| 有破坏性但后端能撤销 | 先执行，再给带「撤销」的通知，关闭后仍有常驻撤销入口 |
| 不可逆，影响小 | 贴着按钮的气泡确认 |
| 不可逆，影响大 | 对话框：标题写明对象，确认按钮写「删除 xxx」，默认焦点在「取消」 |
| 极其危险（删库、清空） | 要求输入对象名称后才能确认 |
| 某个字段填错 | 字段下方的行内提示，不自动消失 |
| 重要操作失败 | 横幅、行内提示或对话框，不能只用自动消失的轻提示 |
| 批量操作部分失败 | 按成功、失败、未知 [分组展示](complex-components.md#分组展示执行结果)，只重试未成功项 |
| 次要模块不可用 | 只替换受影响的块，见 [错误与降级](patterns.md#7-错误与降级) |
| 全局故障或断网 | 页面顶部横幅 |

危险操作的顺序固定为：能撤销就不确认，见 [危险操作](patterns.md#2-危险操作能撤销就不要确认)。

### 3.5 等待与保存

| 如果 | 那么用 |
|---|---|
| 等待短于 300ms（默认） | 只给按下反馈，不显示加载指示 |
| 300ms 到 2 秒，范围小 | 按钮忙碌态或小型 spinner，只锁住受影响的行或按钮 |
| 300ms 到 2 秒，整块内容 | 形状接近真实内容的骨架屏 |
| 超过 2 秒 | 加一句正在做什么；能估算就用进度条 |
| 很长 | 可取消、可后台运行，完成时通知 |
| 刷新已有数据 | 保留旧内容，失败时不显示成空状态 |
| 成功率高、失败可恢复 | [乐观更新](async-feedback.md#乐观更新与回滚) |
| 涉及金钱、对外发送或不可逆 | 等服务端确认后再显示成功 |
| 开关类设置 | 即时生效 |
| 文本框、单选组、复选组、下拉框 | 显式保存；同一表单不混用两种模式 |
| 长表单或复杂流程 | 自动保存草稿，提交仍为显式操作 |
| 有未保存的修改 | 离开页面和站内跳转都提醒 |

加载分级见 [加载](patterns.md#3-加载)，保存规则见 [保存](patterns.md#4-保存)。

### 3.6 没有内容或出了错

先判断原因再选入口，文案写法见 [空状态文案](content.md#错误与空状态文案)。

| 原因 | 给什么入口 |
|---|---|
| 首次使用 | 说明用途，加一个创建入口 |
| 筛选后为空 | 清除筛选 |
| 任务已全部完成 | 说明这是正常情况，可返回工作区 |
| 没有权限 | 申请权限，不提示创建 |
| 尚未配置 | 去配置 |
| 加载失败 | 重试；已有数据写「暂时无法加载」，不显示成空 |

## 4. 状态矩阵

写代码前，对每个区块逐项回答「这个状态长什么样」。答不出的就是漏掉的设计。

| 状态 | 要回答的问题 |
|---|---|
| 默认 | 最常见的数据量下是否一眼看到主操作 |
| 加载 | 首次加载和刷新分别显示什么，300ms 内和 2 秒后各是什么 |
| 空 | 属于 3.6 的哪一种原因 |
| 错误 | 整页、局部、字段三个范围各怎么提示，输入是否保留 |
| 部分成功 | 批量或多文件时如何区分成功、失败、未知 |
| 禁用与无权限 | 是否说明原因；键盘和程序激活是否都被拦截 |
| 极端内容 | 超长文本、0 条、上千条、超大数字是否撑破布局 |
| 窄屏与触屏 | 320 CSS px 下功能是否齐全，点击区域是否够大 |
| 键盘 | 只用键盘能否走完主流程，焦点去向是否合理 |
| 暗色与偏好 | 暗色、减少动效、强制颜色下是否可用 |

## 5. 方案单

实现前按下面的格式写出方案单并给用户看。用户只回「可以」就按它实现；有异议只改对应行。

```text
任务陈述：谁 / 场合 / 对象 / 动作 / 频率 / 做错的代价
事实与假设：六个事实，逐条标注「已确认」或「假设」
需求类型与骨架：命中第 2 节哪一行，页面由哪些区块组成
关键判断：每条一行「因为……所以用……」，注明出自 3.x 哪一行
状态矩阵：只列本需求涉及的状态及其处理
加载的参考：实际读取的专题文件
例外：偏离默认的地方及理由；不适用的清单项
```

## 6. 示例

**给订单列表加批量删除。** 类型：管理一批记录。因为后端有软删除，所以先执行再给带撤销的通知，
不弹确认框；因为可能部分失败，所以结果按成功、失败、未知分组并只重试失败项；因为列表有分页，
所以表头用三态复选并写明选中的是当前页还是全部结果。

**做一个通知偏好页面。** 类型：修改偏好。因为各项都是互不依赖的二选一，所以整页用开关即时生效，
页面上不再放保存按钮；因为即时生效仍可能失败，所以失败时把开关退回原状态并在该行给出不自动消失的提示。

**在 AI 客户端里加文件上传。** 类型：上传，并入对话骨架。因为键盘用户无法拖放，所以输入框旁放文件选择按钮，
拖放只作附加入口；因为上传完成不等于模型可读取，所以每个文件分别显示上传中、处理中、完成、失败；
因为失败后用户还要继续发消息，所以保留文件名和重试入口，不清空已输入的文字。

## 7. 冲突与例外

- 规则互相冲突时，优先级为：无障碍 > 可用性 > 一致性 > 质感。
- 项目里已有成熟模式时沿用它，即使与本文件的默认不同；只有它违反无障碍或会丢用户输入时才提出替换。
- 两个方案都说得通时，选更轻、更可逆、更接近原生控件的那个。
- 需求不在任何一张表里时，把它拆成表内的子问题；仍然判断不了就说明卡在哪里并询问用户，不凭感觉选。
- 用户明确指定了界面形式时照做；它与规范冲突的地方在方案单的「例外」里写明后果。
